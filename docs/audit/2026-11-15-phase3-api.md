# Phase 3: API Baru (Login Dummy, Sesi, List & Detail)

Tanggal: 2026-11-15 | Branch: `checkreview` | Spesifikasi: `docs/PHASE_3_BRIEF.md`

## Lingkup

Login dummy berbasis sesi dan endpoint baca (read-only) di
`src/brigid/interfaces/web/app.py`, plus tes baru `tests/test_web_api.py`.
Tidak ada perubahan pada `src/brigid/guard/`, `tools/`, `agent/`, atau `src/brigid/app.py`.
Tidak ada endpoint tulis baru; pembayaran tetap hanya lewat chat, `propose_payment`, dan guard.

## Desain

- Akun demo: tabel `DEMO_ACCOUNTS` di `app.py` (email, password, role, name sesuai tabel
  spesifikasi; name konsisten dengan `data/seed/users.csv`). Principal selalu diambil dari
  `principals.get(role)` sehingga tetap bekerja dengan fixture tes maupun seed produksi.
- Sesi: `dict[str, Principal]` di memori + `threading.Lock`; token `secrets.token_urlsafe(32)`;
  cookie `brigid_session` (`httponly`, `samesite="lax"`, `path="/"`); token juga diterima lewat
  header `Authorization: Bearer`.
- Kompatibilitas endpoint lama (`/api/chat`, `/api/pending`, `/api/confirm`, `/api/cancel`,
  `/api/mandate`, `/api/reset`): field/query `role` kini opsional. Sesi valid menang; `role`
  yang berbeda dari sesi ditolak `403`; tanpa sesi dan tanpa `role` dijawab `401`; tanpa sesi
  dengan `role` berjalan seperti sebelumnya. Seluruh tes lama tetap lulus tanpa perubahan
  perilaku.
- Endpoint baru: `POST /api/login`, `POST /api/logout`, `GET /api/me`, `GET /api/invoices`,
  `GET /api/invoices/{id}`, `GET /api/transactions`, `GET /api/transactions/{id}`,
  `GET /api/suppliers/{id}`. Semua wajib sesi (`401`).
- Mapping error environment: `AccessDenied` 403, `NotFound` 404, `ToolFailure`/`ToolTimeout`
  503 (satu helper `read_env`).
- Masking: helper `mask_account` mengambil 4 karakter alfanumerik terakhir (`•••• XXXX`,
  `••••` bila lebih pendek). Dipakai untuk `stated_account` dan `verified_account`.
- Screening: `document_text` invoice dan `memo` transaksi disaring lewat
  `app.guard.screen_untrusted(..., session_id="web-api:{user_id}", source="data")`; hanya
  `needs_review: bool` yang diekspos.
- Middleware CSRF `guard_requests` dan security headers tidak berubah dan tetap berlaku untuk
  semua route baru (`/api/login` dan `/api/logout` juga mewajibkan `Content-Type: JSON`).

## Keputusan & catatan

- Password dibandingkan dengan `hmac.compare_digest` pada byte.
- `avg_invoice_amount` dan `amount` diserialisasi lewat `model_dump(mode="json")`
  (Pydantic menghasilkan string, mis. `"1500000"`), sesuai spesifikasi
  "(string/number JSON)".
- Spesifikasi meminta `document_text` dikembalikan apa adanya, tetapi teks dokumen inv-0094
  memang memuat nomor rekening palsu di dalam kalimatnya. Field terstruktur `stated_account`
  tetap ter-mask; nomor yang muncul di teks dokumen adalah bagian dari konten tidak tepercaya
  yang justru ditandai `needs_review`. Tes `test_supplier_accounts_never_appear_in_full`
  memastikan nomor rekening terdaftar supplier tidak pernah muncul utuh di response.
- Dua tes lama di `tests/test_interfaces_gaps.py` diperbarui mengikuti spesifikasi baru:
  `/api/pending` tanpa `role` dan tanpa sesi kini `401` (sebelumnya `422`), dan teks peringatan
  `main()` diperbarui karena halaman kini punya login dummy ("act as any role").
- Peringatan `main()` diubah dari "has no login" menjadi kredensial demo bersama, karena
  perilakunya memang berubah.

## Tes

`tests/test_web_api.py` (32 tes): login sukses ketiga role, kredensial salah/field ekstra,
`/api/me` via cookie dan Bearer, tanpa sesi 401, logout membatalkan sesi, endpoint lama dengan
sesi tanpa `role`, penolakan role yang tidak cocok (403), 401 tanpa sesi/role, invoices filter
kind/status disandingkan dengan environment, staff hanya receivable + 403 payable + 404 detail
payable, masking `stated_account`, `needs_review` untuk invoice bertanda (inv-0094),
detail payable dengan supplier ter-mask, supplier tidak dikenal pada invoice, transactions
filter direction/from/to, default 90 hari, from>to 422, staff 403, id tidak dikenal 404,
suppliers ter-mask, staff 403, id tidak dikenal 404, ToolFailure 503.
